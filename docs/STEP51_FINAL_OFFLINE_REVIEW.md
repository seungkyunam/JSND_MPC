# Step 51 — 통합 MPC 오프라인 최종 검토 / 실차 적용 대기

기준: GitHub `integrated-mpc-v3` 최신 `de416d9d60015c0134c1cc0a8562afbb14d3b596` (Step 50).
작업: `step51-mpc-final-validation`, 2026-11-26. 기존 작업 트리 보존, 차량 접속·배포·구동 없음.

## 판정

- **기본 적용 후보**: 짧은 트랙의 지나간 장애물 재인식 수정, MPC 내부/출력 계층 진단 기록. 기존 통합 가속·조향 최적화, 장애물 회피 로직, TTC/E-STOP, 물리 한계 유지.
- **가속 개선 구현 완료, 기본 비활성**: `mpc_time_weighted_accel_cost`. 첫 20 ms 제어 구간에 50 ms 미래 구간과 같은 가속 비용을 부과하는 불균형을 시간 비례로 수정. `step51_5p0` 프로파일로만 선택한다. 비용 감소만으로 한계를 올리거나 출력에 게인을 곱하지 않는다.
- **고속 실차 준비 완료 판정은 보류**: 개선안의 모의 차량 결합 가속 한계 위반, 지연 불확실성, 실제 트랙의 장애물 전환 재현 데이터 부족이 남았다. 최적화 내부의 물리 제약 통과와 지연 있는 실제 차량의 제약 만족은 다르다. 실차 67% 코너 정지 해소를 증명했다고 주장하지 않는다.
- **2배 출력 채택 금지**: 실험은 오프라인 스크립트에만 존재. ROS 제어기/프로파일에는 출력 배율 기능을 추가하지 않았다.

## 1. 기존 로그에서 확인한 사실과 확인할 수 없는 것

Step 50 분석 및 원본 `docs/logs/step49_run_5p0_20261125_163051.log.txt`를 기존 `step50/met.py`로 확인했다. 자율 140.6 s, 12랩, 최고 6.71 s, 중앙 11.50 s, 최고 관측속도 3.13 m/s. STOP 요청 81회(34.6/min), 0.5 s 간격으로 묶은 40개 사건. `trailing_without_target` 17회, 제동 엔벨로프 12회, deadline 12회, OSQP 9회, TTC 17회. STOP **틱 수가 아닌 상태변경 로그 횟수**다. TTC 로그는 throttle로 실제 개입 횟수를 적게 나타낼 수 있다.

Step 49 로그에는 최적 가속도, 예측 속도, 정확한 제한 전 명령, 같은 조건의 PP 출력이 없다. 실차 위치는 로그 기반 추정이다. 따라서 같은 실제 시각의 PP/MPC 비교나 0.5 m/s 제한의 실차 포화율은 복원할 수 없다. Step 48/49의 sparse 로그 분석을 다시 만들어 수치가 있는 것처럼 취급하지 않았다.

## 2. 가속/속도 병목

`q_speed=8`은 이름과 달리 속도 제곱오차가 아니라 **경로 접선 방향 진행거리의 선형 보상**이다. 속도 상태의 quadratic weight는 0이며, 위치 비용은 도달 가능한 가속 속도열로 만든 미래 위치를 추종한다. 따라서 `q_speed`만 키운다고 속도 명령이 두 배가 되지 않는다. 최종 가속 입력은 forward-Euler 위치 모델의 마지막 위치에 영향을 주지 않으며, 첫 20 ms 입력은 이후 50 ms 입력에 비해 같은 a² 비용당 진행 효과가 작다. 짧은 첫 입력을 작게 하고 미래 입력을 크게 잡는 구조적 편향이 있다.

시간 비용 개선은 `r_accel[k] = r_accel * dt[k]/preview_dt`만 바꾼다. 현재 12단계에서 첫 비용 0.05→0.02, 나머지 0.05 유지. 속도/가속/감속/조향/조향속도/마찰/heading/tracking/terminal braking/비선형 검증은 그대로다. 기본 false는 기존 Hessian과 동일하다. 미확인 파라미터 최적화를 기본 설정에 반영하지 않았다.

20 m 직선, 50 Hz, 동일 차량 모델에서 실제 속도 .5–3 m/s 구간 가속 중앙값:

| 속도 응답 가정 τ | 기존 MPC | 시간 비용 개선 | 선행 제한만 1.0 | 저크 제한 해제 |
|---|---:|---:|---:|---:|
| 0.12 s | 3.41 | 4.00 | 3.41 | 3.42 |
| 0.45 s | 1.11 | 1.11 | 2.22 | 1.11 |

τ=.12에서 3 m/s 도달 1.06→0.92 s. τ=.45에서는 최적 가속 3.45→5.00이어도 실가속 1.11로 같고, 선행 제한 포화율 약 80%. 단순 1차 모델에서 `a ≈ (v_cmd-v)/τ`, 따라서 .5/.45≈1.11이다. **τ=.45는 실차 1.09와 비교하기 위한 민감도 가정이지 측정·식별 결과가 아니다.** 이 조건에서 선행 제한 확대는 직선만 개선하고 코너 폐루프는 실패했으므로 채택하지 않는다.

기존 `lap_sim.build`가 실차 `mpc_accel_jerk_mps3=20`을 전달하지 않는 누락을 수정했다. 이 저크는 양의 가속을 0→5에 최소 .25 s 걸리게 하지만 감속은 제한하지 않는다. 정상 응답 직선에서는 제거해도 가속 중앙값은 거의 같고 출발 시간만 0.08 s 짧아졌다. 코너마다 필터를 추가하는 해법은 쓰지 않았다.

단일요인 비교(`ablations.jsonl`, test0, 자세 지연 0, 서보 60 ms)는 q_speed 두 배 / r_accel 절반 / 위치비용 절반 / 저크 해제 / 선행 제한 1.0 / 조향 preview 0 / brake lead 0 / horizon 16을 각각 분리했다. 기존 flying lap 약 11.42 s에 대해 q_speed 16은 11.40, r_accel 절반 11.34, 위치비용 절반 11.54, horizon 16은 11.40이다. 최고속도는 모두 5.0에 도달한다. 작은 wall-clock STOP 변동이 있어 작은 랩 차이를 유의한 실차 개선으로 보지 않는다.

2배 출력은 직선에서 9.52 m/s 명령 및 5.36 m/s 실제 속도 후 제동 엔벨로프 실패. test0에서는 5.45 m/s, 횡가속 5.54 m/s², 50 STOP 사건, 0랩. 출력 배율은 MPC가 검증한 계획과 액추에이터 입력의 일치를 깨뜨린다. 5 m/s에만 clip해도 곡률/가감속/마찰 제약은 보장되지 않는다.

## 3. 조향 선행 및 코너 스무스

현재 history predictor는 **하나의** .18 s 구간을 실제 발행 명령 이력으로 적분한다. 여기에 별도 자세-age 외삽을 다시 더하지 않았다. `d=vτ`이므로 1/3/5 m/s에서 위치 예측 거리는 .18/.54/.90 m. `mpc_steer_preview_s=.03`은 추가 위치 이동이 아니라 조향 선형화/feed-forward의 곡률 참조를 .03/.09/.15 m 앞에서 읽는다. 비용의 위치·heading 참조 전체를 옮기지 않는다. 두 항을 같은 지연 보상으로 계속 늘리면 과선행 위험이 있다.

예측 시간은 .02+11×.05=.57 s. 1/3/5 m/s에서 대략 .57/1.71/2.85 m를 보지만, 곡률 감속 상한은 **지역 경로 전체** 역방향 제동 패스와 끝점 정지 여유로 계산한다. brake lead .12 s는 속도에 비례해 곡률 상한을 더 일찍 적용한다. horizon만 늘려 사전 감속 문제를 해결한다고 볼 수 없다.

자세 120 ms + 서보 60 ms 가정에서 시간 비용 개선은 진입/중앙/탈출 평균 횡오차를 줄였지만, 자세 지연이 0인 조건에서는 최대 횡오차가 .152→.311 m, 횡가속 4.64가 됐다. 자세 140 ms 조건에서는 flying-lap 최대 횡오차 .186→.214 m로 악화했다. 추가 preview 확대나 지연 추정값 변경은 적용하지 않았다. 실제 지연 식별 전에는 빠른 안을 기본 활성화할 근거가 부족하다.

## 4. 정지 원인과 변경 범위

**재현된 코드 오류**: 기존 horizon=min(설정거리,L−2). L=13.9, ego s=7, 이미 지난 장애물 s=4.1이면 gap=11.0<11.9라 여전히 앞 장애물. GB가 막혔고 새 회피 경로가 없으면 TRAILING으로 분류될 수 있다. 수정은 horizon=min(설정거리,L/2,L−rear_exclusion)로 전방 반랩을 사용한다. 출발선 wrap(ego13.5, 장애물.2), 실제 앞/근접 장애물은 유지하는 테스트를 추가했다. 장거리 앞 장애물은 반랩 안으로 들어올 때 관심 대상으로 편입된다. TTC/E-STOP의 센서 경로는 바꾸지 않았다.

상태 전환 테스트에서는 이전 필터로 남은 장애물이 TRAILING을 만들고, 수정 필터로 제거하면 경로 복귀 조건이 만족된 OVERTAKE가 GB_TRACK으로 돌아간다. **실차 s≈7 당시 대상 ID/gap가 미기록이므로 해당 실차 사건의 확정 원인은 아니다.** 회피 경로에서 GB로 복귀할 때 heading/위치 불일치가 있으면 기존 recovery/STOP은 여전히 필요하다. 장애물이 없다는 이유만으로 무목표 TRAILING을 무조건 주행시키거나 엔벨로프를 넓히지 않았다.

- `NO_STATIC_PATH`: 회피 경로 가용성 실패 원인. 통과 후 잘못 남은 장애물 때문에 요구되는 경우를 제거하는 수정이며, 실제 경로가 없는데 위험한 회피를 허용하지 않는다.
- `trailing_without_target`: 기존 최대 감속 soft STOP 후 .2 s 이내 0 유지. 원인 없이 grace 시간을 늘리지 않았다.
- heading/braking envelope: OVERTAKE→TRAILING의 경로·속도 상한 급변이 원인일 수 있으나 실측 경로 없음. Step 35/49의 bounded braking recovery/계획 연속만 유지한다.
- OSQP/deadline: 기존 10틱 bounded continuation, 비선형 재검증 및 예산 유지. 실차 조기 STOP을 없애기 위해 무조건 오래된 명령을 내보내지 않았다.
- TTC 17회는 `/scan` 없는 로그로 오검출이라고 판정할 수 없다. 변경하지 않았다.

## 5. 동일 조건 비교와 물리 감사

실차 `11_18_6` 맵/Step49 bag은 로컬 및 해당 브랜치에 없으므로 저장소 `test0` 사용. 실제 제어기 코드, 50 Hz, 동일 시작 상태·경로·seed0·2 cm 위치잡음·서보60 ms·자세120 ms·속도응답τ=.12. MPC 실행 예산 16 ms/OSQP 8 ms. PP는 동일 5 m/s 및 기하 횡가속4.5 상한의 입력 속도계획으로 비교했다. PP 출력 자체에 MPC 안전제약을 덧붙여 다른 제어기를 만들지는 않았다. 공통 입력 속도열은 통합 MPC가 사용하지 않는다.

별도 동일 상태 프로브는 경로 각 위치, 측정속도1/2/3, 같은 이전 조향/속도명령에서 PP·MPC를 호출한다. `same_state.json`에 최적가속/예측속도열/저크 적용/제한 전후 속도가 있다. 폐루프 랩 비교와 혼동하지 않는다. `profiles_real.png`에 위치별 속도·횡오차·조향 프로파일을 제공한다. 결과/스크립트 정의: [step51 README](../jsnd_int/tests_offline/step51/README.md).

## 6. 검증 및 현장 남은 확인

관련 회귀 테스트 68개 통과: 실제 solver의 물리/볼록성/속도독립성/장애물 캡/계획 연속/안전 실패, history prediction, odom/mux guard, 래핑 및 상태 전환, 개선 후보의 비선형 마찰·조향 제약. 기존 테스트의 Step35/49 이전 가정(2틱 continuation, 즉시 STOP, .1 s default)을 현재 의미로 갱신했다. 새 코드를 통과시키기 위해 생산 안전 기준을 낮추지 않았다. 기존 배포 도구에 manifest 선택만 추가했고 임시 디렉터리에서 적용·복구·로컬 변경 보호 3개 통과. ROS2/Jetson 빌드와 차량 구동은 실행하지 않았다.

현장에서 필요한 것은 새 원인 추측용 무기록 주행이 아니라 기록을 동반한 확인이다:

1. 사용자 승인 후 기본 5p0(비용 개선 OFF)로 래핑 수정 검증: s≈7의 target ID/gap, 실제 front obstacle 보존, OVERTAKE 종료 경로와 무목표 TRAILING 횟수.
2. 같은 bag으로 진단 `optimal_accel`, `applied_accel`, `predicted_speed`, `command_unclipped/clipped`, `trailing_cap`, `guarded_speed`와 mux 뒤 명령/실속도를 대조. lead 포화와 최적화 가속 부족을 구분.
3. 명령→조향/요레이트 및 자세 timestamp 지연, 속도 응답을 확인. 지연 불일치·결합제약 위반이 해소되기 전 `step51_5p0` 고속 후보는 승인 대상으로 보지 않는다.
4. 실제 장애물·TTC 개입은 유지. 빠른 PP와 실차 비교는 같은 맵/경로/속도 상한/배터리/기록 조건에서만 수행.
